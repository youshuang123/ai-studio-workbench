## 4. 本阶段做了什么

**后端（4 张新表 + 1 个路由模块）**
- `dramas` / `drama_scenes` / `drama_shots` / `drama_characters`
- **镜头只存 `job_id`**，关键帧的生成、精修、质检、成本全部复用既有机制（这是工作量能压住的关键）
- 分镜表生成：LLM + 严格 schema 校验 + 失败重试 1 次 + 非法值回退（景别/机位/时长）
- 镜头 CRUD + 重排；**改内容会清空该镜头的旧关键帧**（避免图文不符）
- 角色参考图（文生图 ¥0.03）
- 关键帧批量生成（只为缺失的生成）
- 轻动效合成：按景别选运镜（远景推近 / 中景平移 / 近景推近上移）+ 0.4s 转场
- 导出 ZIP：分镜表 CSV + 关键帧 + 成片

**前端（2 个新页面）**
- 短剧列表 + 新建（粘剧本）
- 短剧详情五段式：01 剧本 / 02 分镜表（行内编辑）/ 03 角色 / 04 关键帧网格 / 05 成片

## 5. 已知问题

| 问题 | 说明 |
| --- | --- |
| **角色一致性只是"参考图"** | 不是 LoRA。6 个镜头的人物长相不保证完全一致，只是 prompt 里描述了同一个角色 |
| 输出**无声** | 未接 TTS，属 P1 |
| 第 6 镜出现"方案"两字 | 分镜 action 里明确要求"写着方案两字"，模型照做了 —— 这是内容需求，不是违规 |
| 分镜表 390 需横向滑动 | 7 列表格在手机上无法压缩，已加横向滚动容器 |
| 不是生成式视频 | 关键帧 + 推拉/转场，商品和人物不会真的动 |
