## 3. 真实调用与发现

### 3.1 三次真实精修的结果

| 序号 | 做了什么 | 结果 | 花费 |
| --- | --- | --- | --- |
| 1 | 预研：原图 → 图生图 | 保留形状颜色，**无乱写字** | ≈¥0.30 |
| 2 | 正式链路第 1 次精修（原 prompt） | ΔE 0.4 / QA 11/12；**但顶部出现大字「厚装家居」** | ¥0.30 |
| 3 | 加强 prompt（中英双语 + 大写禁止）后再精修 | **QA 14/15，无文字** | ¥0.30 |

### 3.2 两个必须记录的发现

**发现 1：即使 prompt 明令禁止，图生图仍可能加文字（第 2 次）**

- 第 2 次精修图上出现「厚装家居／厚/薄不烫手」大字
- **VLM 质检抓住了**：`no_text_or_watermark` 扣到 2/3，并列出 issue「图片顶部有文字和装饰性图案」
- 说明质检维度设计有效
- 第 3 次把约束改成中英双语 + 全大写 `ABSOLUTELY NO TEXT` 后，文字消失

**发现 2：ΔE「主色差」对浅色/白色商品不可靠**

- 实测：两张都是米白马克杯（一张灰背景、一张白背景），ΔE 算出 **34.6 → 判为"颜色不一致"**
- 同期 VLM 五维里的 `color_consistency` 判 **3/3 完全一致** —— 与肉眼判断一致
- 根因：主色提取必然混入背景/阴影/水印；浅色商品与浅色背景几乎无法靠颜色分离
- **处理**：
  1. ΔE 降级为**参考值**，界面用中性灰标签、文案标「（参考）」，不再做红/绿判定
  2. 真正的颜色判断改由 VLM 的 `color_consistency` 维度承担（传草稿图 + 精修图双图）
  3. 算法改了三版（纯白剔除 → 中心优先 → 四角背景基准），每版的问题都写成了测试锁住

## 4. 本阶段做了什么

**后端**
- 精修通道：`generate_edit()`（Qwen-Image-Edit，图生图），复用现有 Key
- 精修 job：`stage=refined` + `refined_from` 指向草稿，草稿永远保留
- 自动质检：精修成功后自动跑 ΔE + VLM，结果写入 `delta_e / qa_score / qa_detail`
- 五维质检：符合描述 / 无文字水印 / 商品完整 / 背景干净 / **颜色一致（双图对比）**
- 按平均分判定 pass / warn / fail（维度数变化时阈值不失真）
- 批量精修：`POST /api/batches/{id}/refine`，最多 20 条，受批次精修预算 ¥5 约束
- 数组列自动补 5 个字段，不需要重建库

**前端**
- 单张页：精修入口 + 价格明示 + 草稿/精修并排 + 五维明细 + 问题列表
- 批量页：勾选 + 「已选 N 张（精修约 ¥X）」+ **执行前弹窗二次确认价格**
- ΔE 标签改中性「参考」，颜色结论以 QA 为准
