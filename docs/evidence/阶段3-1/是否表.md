## 4. 本阶段改了什么

**后端（小改，不改既有契约）**
- `generation_jobs` 新增 `cancel_requested` 列（启动时自动补列，幂等）
- 新增 `POST /api/jobs/{id}/cancel`：
  - `queued` → 直接 `cancelled`（零费用）
  - `running` → 置 `cancel_requested`，执行器在检查点丢弃产物、不记账
  - 已结束 → 409
- SSE 新增 `cancelled` 事件（此前取消会被当成 `error`）
- 执行器加检查点：模型返回后再看一次是否被取消

**前端**
- `useJobEvents` 重写：
  - 服务端 `error` 与「连接断开」靠是否带 `data` 区分
  - **断线不猜结果**：先 `GET /api/jobs/{id}` 回查真实状态，仍在跑才重连（最多 2 次），仍失败显示 `disconnected`
  - 新增 `stopWaiting()`：只关连接
- `ResultPanel` 支持 6 种 phase（idle / status / done / error / cancelled / disconnected）
  - 不可重试的错误（预算不足、未配 Key 等）**不显示重试按钮**
  - **cancelled 不再被"最近一次成功结果"覆盖**（这是本次发现并修掉的 bug）
- 页面新增「停止等待 / 取消任务」双按钮，并在界面上解释两者区别
- 错误文案改进：5xx 不再笼统写"内部错误"，改为"服务暂时不可用，请确认后端已启动"
- 无障碍：`role="status"`/`role="alert"`、`aria-live`、`aria-busy`、焦点环
- 测试从 19 → 28 条（新增 ResultPanel 8 条 + 状态映射 3 条）
