## 3. 本阶段做了什么

**后端（全新）**
- FastAPI + SQLAlchemy + SQLite，5 张表：`projects` / `assets` / `generation_jobs` / `price_rules` / `usage_records`
- 资产上传三重校验：扩展名 + Pillow 真实解码 + MIME 一致；≤10MB、单边≤8000px；磁盘名一律 UUID（防路径穿越）
- 预算守卫（纯函数）：单价使用「分」整数，避免浮点误差；超限停止，保留已完成结果
- T2I 客户端：OpenAI 兼容接口、`trust_env=False`（不过代理、数据不出境）、超时 60s、有限重试 2 次、错误码归一化（401/403→MODEL_AUTH_FAILED，429→MODEL_RATE_LIMITED，5xx→MODEL_UPSTREAM_ERROR）
- 任务执行：DB 任务表 + 后台线程；启动时把残留 `running` 标记为 `failed(INTERRUPTED)`，不假装还在跑
- SSE：`status → done | error`，10 秒心跳，180 秒超时保护，**任何路径都以 done/error 收尾**
- 统一错误结构 `{"error":{"code","message"}}`，全局异常处理器不泄露堆栈
- 41 条 pytest（预算 7 / prompt 6 / 项目 9 / 资产 10 / 生成 9）

**前端（全新）**
- Next.js 16 + React 19 + Tailwind 4 + TS strict；同源代理 `/api/*` → 8000
- 项目列表（空态 / 骨架 / 失败重试）、项目详情（上传 → 表单 → 生成 → 预览 → 下载）、历史（产图 + 任务表）
- SSE 客户端：区分「服务端 error 事件」与「连接断开」（靠是否带 data）
- 统一错误归一化 `lib/api/client.ts`；未知任务状态走 `stale`
- 19 条 vitest（格式化 9 / 状态映射 5 / 错误归一化 5）
- 关闭 Next.js 16 自动生成 `AGENTS.md`（`agentRules: false`），避免污染仓库

**工具**
- `scripts/restart-check.sh` 重新实现（上一版随旧项目删除）：临时 DB + 临时数据目录 + 端口 8977，不碰真实数据、不调模型
