## 〇、这份文档解决什么问题

2-1/2-2 出的图有两个硬伤，预研已经实测确认：

| 问题 | 证据 | 图生图能否解决 |
| --- | --- | --- |
| **不像原商品** | 文生图只认识"深蓝色杯子"这个概念 | ✅ 保留颜色、形状、杯盖结构 |
| **模型乱写字** | prompt 明确禁止「文字」，仍出现「24小时保温」 | ✅ 精修后没有文字 |

**但图生图贵 10 倍**（¥0.3 vs ¥0.03）。所以走**两段式**：

```
草稿（文生图 ¥0.03/张）→ 你挑 → 精修（图生图 ¥0.3/张）→ 质检 → 只留合格的
```

20 张的真实成本 ≈ 20×0.03 + 5×0.3 = **¥2.1**，而不是全精修的 ¥6。

## 一、阶段目标

### 交付范围

| # | 能力 | 对应 PRD |
| --- | --- | --- |
| 1 | 单条**精修**（用草稿图 + prompt 让图生图重绘） | FR-005 |
| 2 | **颜色一致性量化**（ΔE，本地计算，免费） | FR-005 验收标准 |
| 3 | **VLM 质检打分**（符合描述 / 无文字水印 / 商品完整 / 背景干净） | FR-010 |
| 4 | 质检不合格 → 标红 + 单条重试 | FR-010 |
| 5 | 批量里对选中的行批量精修 | FR-004 延伸 |
| 6 | 精修成本单独记账（和草稿分开） | FR-012、FR-015 |

### 验收标准

| 指标 | 标准 | 怎么测 |
| --- | --- | --- |
| 精修后保持商品特征 | 你肉眼看"是不是同一个商品" | 你点 3 次精修 |
| 精修后无乱写字 | VLM 判定"有文字"= 不合格 | 自动 + 你复查 |
| 颜色一致性 | 与草稿图主色 **ΔE ≤ 3** | 自动计算显示 |
| 质检可用 | 4 个维度各 1-3 分，总分 <6 标黄、<4 标红 | 看界面 |
| 成本可见 | 草稿成本、精修成本分开显示 | 对比账单 |
| 精修不影响已完成 | 原草稿图保留，可对比 | 点开对比 |

### 明确不做

- ❌ logo OCR 专项（用 VLM 的"是否有文字/水印"维度替代，避免引入 OCR 依赖）
- ❌ DINO / ArcFace 形状与人物相似度（需自建模型，与"不自建 GPU"冲突）
- ❌ 自动全量精修（费钱，必须人工挑）
- ❌ 短剧线（2-4）

## 二、技术方案

### 2.1 模型（都在现有 Key 下，无需新 Key）

| 用途 | 模型 | 单价（估算，待核账单） |
| --- | --- | --- |
| 草稿 | `Tongyi-MAI/Z-Image-Turbo` | ¥0.03/张 |
| **精修** | `Qwen/Qwen-Image-Edit-2509` | **≈¥0.3/张**（实测 27.2s） |
| 质检 | `Qwen/Qwen3-VL-8B-Instruct` | ≈¥0.002-0.005/张 |

配置项（`.env` 新增）：

```dotenv
MODEL_EDIT_BASE_URL=https://api.siliconflow.cn/v1
MODEL_EDIT_API_KEY=          # 留空则复用 MODEL_T2I_API_KEY
MODEL_EDIT_NAME=Qwen/Qwen-Image-Edit-2509
MODEL_EDIT_UNIT_PRICE=0.30

MODEL_VLM_BASE_URL=https://api.siliconflow.cn/v1
MODEL_VLM_API_KEY=           # 留空则复用 MODEL_T2I_API_KEY
MODEL_VLM_NAME=Qwen/Qwen3-VL-8B-Instruct
MODEL_VLM_UNIT_PRICE=0.003

DELTA_E_THRESHOLD=3.0        # 颜色一致性阈值
```

### 2.2 精修流程

```
用户点「精修」
  → POST /api/jobs/{id}/refine
  → 校验：原 job 必须 succeeded 且有 output_asset_id
  → 预算检查（精修单价 ¥0.30）
  → 新建 job（stage=refined, refined_from=原 job id），入队
  → 调 Qwen-Image-Edit：输入=草稿图的 data URL + 精修 prompt
  → 存图（kind=output, stage=refined）
  → 自动触发质检（ΔE + VLM）
  → 返回新 job
```

**精修 prompt**（在草稿 prompt 基础上追加约束）：

```
把这张商品图重新拍摄成电商主图：
纯白背景、影棚布光、商品居中占画面 70%；
严格保持商品的形状、比例、结构、颜色（{color}）不变；
不要添加任何文字、logo、水印、促销标签、人物。
```

- 阈值：≤3 判"颜色一致"，3-6 判"轻微偏差"，>6 判"颜色不一致"
- 纯函数，单测覆盖（背景剔除、纯白图、单色图、多色图）

### 2.4 VLM 质检

输入：精修图（base64）+ 固定 prompt，要求返回严格 JSON：

```json
{
  "follows_description": 3,
  "no_text_or_watermark": 2,
  "product_complete": 3,
  "background_clean": 3,
  "issues": ["右下角有淡淡的 AI 生成水印"],
  "verdict": "pass"
}
```

| 维度 | 1 分 | 2 分 | 3 分 |
| --- | --- | --- | --- |
| follows_description | 明显不是描述的商品 | 大致相似 | 完全一致 |
| no_text_or_watermark | 有明显文字/水印 | 有很淡的水印 | 干净 |
| product_complete | 商品被裁切/变形 | 轻微不完整 | 完整居中 |
| background_clean | 背景杂乱 | 有阴影杂物 | 纯白干净 |

- 总分 = 四项之和（4-12）
- `verdict`: ≥10 pass / 6-9 warn / <6 fail
- 校验失败（非 JSON）→ 记为 `qa_failed`，不阻断精修结果

### 2.5 数据变更

`generation_jobs` 新增 4 列（启动时幂等补列）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `stage` | VARCHAR(16) | `draft`（默认）/ `refined` |
| `refined_from` | VARCHAR(36) | 精修来源的草稿 job id |
| `delta_e` | REAL | 与草稿主色的色差 |
| `qa_score` | INTEGER | 质检总分 4-12 |
| `qa_detail` | TEXT | 质检 JSON 字符串 |

不新建表——精修产物就是另一个 job，天然复用成本、状态、SSE。

### 2.6 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/jobs/{id}/refine` | 精修一条（202，后台执行） |
| POST | `/api/batches/{id}/refine` | 批量精修（body: `{item_ids: [...]}`，最多 20 条） |
| GET | `/api/jobs/{id}` | 已有，增加 `stage/delta_e/qa_score/qa_detail` |
| POST | `/api/jobs/{id}/qa` | 单独重跑质检（免费调用 VLM 除外） |

### 2.7 前端

**单张页**：
- 结果区出现「精修成主图（约 ¥0.30）」按钮
- 精修完成后：并排显示 草稿 / 精修 两张，标注 ΔE 和质检分
- 质检不合格 → 红框 + issue 列表 + 「重新精修」

**批量页**：
- 每张卡片加勾选框
- 底部「精修选中的 N 张（约 ¥X）」按钮（先说清价格再执行）
- 精修后的卡片显示 `ΔE` 与 `QA` 小标签

## 五、验收清单（你照着点）

1. **精修一条** → 点「精修成主图」→ 约 27 秒 → 出现精修图
2. **对比** → 草稿和精修并排显示，能看出"是同一个杯子但更干净"
3. **ΔE 显示** → 精修图旁显示 `ΔE 1.8（颜色一致）`
4. **质检分** → 显示 `10/12`，点开能看到 4 个维度 + 问题列表
5. **有文字会被扣分** → 找个草稿上有字的，看质检是否指出
6. **批量精修** → 批量页勾 2 张 → 点「精修选中的 2 张（约 ¥0.60）」→ 必须先在弹窗里确认价格
7. **成本分开** → 单张页的「累计成本」里，草稿 ¥0.03 和精修 ¥0.30 分得清
8. **失败不影响草稿** → 我注入一次精修失败 → 草稿图还在，可重试
