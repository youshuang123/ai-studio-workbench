# 第 2-1 阶段技术开发文档｜电商线最小闭环（单张主图端到端）

> 配套文档：`docs/PRD/ai-studio-workbench/PRD-v0.2.md`、《技术适配声明》（已确认 2026-10-22）、通用技术栈手册 V2.2。
> 本文档**只覆盖第 2-1 阶段**。AI 开发时不得提前实现批量、短剧线、轻动效等其他阶段能力。

---

## 〇、先说清一件事：原声明里的「2-1」被拆成两刀

《技术适配声明》写的是「2-1 = 电商线最小闭环」。实际开发时它仍然太大，按纵向切片原则再拆：

| 子阶段 | 范围 | 产品经理能看到什么 |
| --- | --- | --- |
| **2-1（本文档）** | 单张主图端到端：建项目 → 上传商品图 → 生成 1 张主图 → 看结果 → 下载 | 一张真的图，能判断好坏 |
| 2-2 | SKU 表批量：试跑确认 → 批量 → 一致性检查 → ZIP 导出 | 一批图 + 成本账单 |
| 2-3 | 短剧线：剧本 → 分镜表 → 关键帧 | 分镜表 + 关键帧 |

理由：批量是另一个可独立验收的增量。先把「一张图对不对」验证透，再谈「一百张」。

### 本阶段打通的主链路片段

```
上传商品图 → 组装 prompt → 预算检查 → 调用 T2I API → 落地图片文件
→ 写入资产记录 → 前端预览 → 下载
```

这一条跑通后，2-2 的批量只是把它循环 N 次并加上并发控制。

### 模型选型

| 用途 | 默认 | 备选 | 说明 |
| --- | --- | --- | --- |
| 文生图（主图） | **硅基流动 SiliconFlow · FLUX.1-schnell** | 阿里云百炼 `wanx2.1-t2i-turbo` | OpenAI 兼容接口 `/v1/images/generations`；按「便宜优先」，FLUX schnell 约 ¥0.01-0.03/张 |

**成本口径**（写进 `PriceRule` 表，页面显示）：

```
单张成本 = API 单价 × (1 + 重试数) + 存储摊销（2-1 记 0）
```

## 六、数据、资产与状态

### 为什么用 SQLite

PRD §9.1 有 11 个实体，2-1 需要其中 5 个。单文件 JSON 无法支持"按项目查资产、按时间排序、成本汇总"。SQLite 单文件、零运维、与过渡档单实例匹配。

### 5 张表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `projects` | id(uuid), name, description, owner_id, created_at, updated_at | 2-1 不做登录，`owner_id` 先填 `"local"`，为 D5 留位 |
| `assets` | id, project_id, kind(upload/output), filename, path, mime, bytes, width, height, sha256, created_at | 上传图和生成图共用；`kind` 区分 |
| `generation_jobs` | id, project_id, status, prompt, negative_prompt, source_asset_id, output_asset_id, model, provider, unit_price_fen, cost_fen, attempts, error_code, error_message, created_at, started_at, finished_at | **金额一律用「分」存整数**，避免浮点误差 |
| `price_rules` | id, provider, model, unit, price_fen, currency, effective_at | 单价来源，页面显示用 |
| `usage_records` | id, job_id, project_id, unit, amount, cost_fen, created_at | 成本归集，2-2 做看板时直接复用 |

**Schema 版本**：`meta` 表存 `schema_version = 1`，方便以后迁移。

### 资产存储规则

| 项 | 规则 |
| --- | --- |
| 目录 | `data/assets/{YYYY}/{MM}/{uuid}.{ext}` |
| 文件名 | UUID，**不用用户原始文件名**（防路径穿越、防中文/特殊字符问题） |
| 格式校验 | 扩展名白名单 + Pillow 真实解码 + MIME 检测，三者一致才接受 |
| 大小上限 | 单张 ≤ 10 MB（PRD 未规定，取保守值，可配置） |
| 尺寸上限 | 单边 ≤ 8000px（防解压炸弹） |
| 生成图 | 统一存 PNG；同目录写同名 `.json` 元数据（prompt / model / seed / cost） |
| 清理 | 2-1 不自动清理（数据量小）；90 天留存规则在 2-2 做定时任务 |

### 状态机（`generation_jobs.status`）

```
queued → running → succeeded
                 ↘ failed          （模型报错/超时，可重试）
                 ↘ over_budget     （预算守卫触发，可重试但需先调高预算）
                 ↘ cancelled       （用户取消，2-1 只做接口占位）
```

**恢复策略**：服务启动时，把所有 `running` 的 job 标记为 `failed`，`error_code = "INTERRUPTED"`，提示可重试。原因：后台线程随进程死亡，不能假装还在跑。

**兼容策略**：前端状态映射遇到未知状态统一显示为 `stale`（"状态未知，请刷新"），不当成成功也不当成失败——沿用上次项目的做法，避免新状态把界面搞崩。

## 七、API / 工具设计

所有接口前缀 `/api`。错误统一 `{"error": {"code": "...", "message": "..."}}`，不返回堆栈。

| # | 方法 | 路径 | 请求 | 响应 | 错误码 |
| --- | --- | --- | --- | --- | --- |
| 1 | GET | `/api/health` | — | `{status, t2i_configured, version}` | — |
| 2 | POST | `/api/projects` | `{name, description?}` | `{id, name, description, created_at}` | 400 VALIDATION_ERROR |
| 3 | GET | `/api/projects` | `?limit=&offset=` | `{items:[{id,name,asset_count,job_count,created_at}], total}` | 500 INTERNAL_ERROR |
| 4 | GET | `/api/projects/{id}` | — | 项目 + 最近 10 个资产 | 404 NOT_FOUND |
| 5 | POST | `/api/projects/{id}/assets` | multipart `file` | `{id, mime, width, height, bytes, url}` | 400 INVALID_FILE / 413 FILE_TOO_LARGE |
| 6 | GET | `/api/assets/{id}/file` | — | 图片二进制（`Cache-Control: private`） | 404 NOT_FOUND |
| 7 | GET | `/api/assets/{id}/download` | — | 附件形式下载 | 404 NOT_FOUND |
| 8 | POST | `/api/projects/{id}/generations` | `{source_asset_id, product_name, category?, selling_points?, color?, budget_cny?}` | `{job_id, status}` | 400 / 402 BUDGET_EXCEEDED / 409 STATE_CONFLICT |
| 9 | GET | `/api/jobs/{id}` | — | job 全字段 | 404 |
| 10 | GET | `/api/jobs/{id}/events` | — | **SSE** | — |
| 11 | POST | `/api/jobs/{id}/retry` | — | `{job_id, status}` | 409 STATE_CONFLICT / 402 |
| 12 | GET | `/api/projects/{id}/usage` | — | `{total_fen, by_model:[…], images}` | 404 |

### SSE 事件序列（第 10 个接口）

```
event: status      data: {"stage":"preparing","message":"正在准备…"}
event: status      data: {"stage":"calling","message":"正在调用模型…"}
event: heartbeat   data: {"ts": 1699...}                  ← 每 10 秒，防代理断连
event: done        data: {"job_id":"…","asset_id":"…","cost_fen":3,"elapsed_ms":8200}
或
event: error       data: {"error":{"code":"MODEL_TIMEOUT","message":"模型响应超时，可重试"}}
```

**规则**：任何情况下都必须以 `done` 或 `error` 收尾，不允许只断开连接。

### 校验规则（Pydantic）

| 字段 | 规则 |
| --- | --- |
| `project.name` | 1-100 字，去首尾空格，不可全空 |
| `product_name` | 1-50 字，必填（不填无法生成有意义的 prompt） |
| `selling_points` | ≤ 200 字 |
| `color` | ≤ 20 字 |
| `budget_cny` | 0.01 - 100，默认取 `TASK_BUDGET_CNY` |
| `source_asset_id` | 必须存在、`kind="upload"`、属于同项目 |

## 八、Prompt 设计

### 主图 prompt 模板（`services/prompt.py`，纯函数，好测）

```
你是电商主图设计师。基于以下信息生成一张商品主图。

商品：{product_name}
类目：{category}
卖点：{selling_points}
主色：{color}

要求：
1. 商品完整居中，占据画面 65%-75%，不裁切
2. 纯白或浅灰渐变背景，无杂物、无文字、无水印
3. 影棚级布光，柔和阴影，商品颜色与参考图一致
4. 正方形构图，1024×1024
5. 不要出现人物、手部、品牌 logo、促销文案
```

- **输入变量**：`product_name`（必填）、`category` / `selling_points` / `color`（可选，空则省略对应行）
- **输出格式**：一段纯文本 prompt，直接传给 T2I API 的 `prompt` 字段
- **负向 prompt**（固定）：`text, watermark, logo, human, hand, blurry, distorted, extra objects, low quality`
- **谁负责解析**：不解析模型输出——T2I 返回的是图片二进制或 URL，不需要结构化解析。这是本阶段只用一个模型契约的原因，风险最低。
- **若启用 LLM 扩写**：`deepseek-chat` 输出必须是一段 ≤ 500 字的 prompt，用 Pydantic 校验长度，超长截断；失败则回退到模板原文（不阻断生成）。

**已知风险**：模板拼装对"商品长什么样"是无知的——模型只能看到文字，看不到上传的图（FLUX schnell 不支持图生图）。所以 2-1 的生成结果**不保证与原商品一致**，颜色/形状一致性要到 2-2 接入支持参考图的模型（Qwen-Image-Edit / FLUX Kontext）才算真正解决。

> **这一点必须让你知道**：2-1 验收的是"端到端链路通 + 成本可见 + 数据不丢"，**不是"图很像原商品"**。一致性是 2-2 的验收项。

| 项 | 内容 |

## 十二、风险与待确认项

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **2-1 出图不保证像原商品** | 你可能觉得"这不是我的商品" | FLUX schnell 是纯文生图，看不到上传的图。2-1 只验链路；一致性在 2-2 接图生图模型后验收 |
| 供应商单价与你账号实际价不一致 | 成本显示偏差 | 单价走 `.env` 可配置；验收时你核对账单，差 20% 我改 |
| 后台线程随进程死 | 生成中重启会中断 | 启动时把 running 标为 failed(INTERRUPTED)，界面提示可重试；不用假进度骗人 |
| 本地磁盘存图片 | 过渡档单实例限制 | 阶段 4 换对象存储；期间每月提醒你备份 `data/` |
| 无登录 | 同一台机器上谁都能用 | 过渡档内部试用 + 只监听 127.0.0.1；对外前必须补 D5 |
| T2I 生成内容不可控 | 可能出现违规图 | 2-1 只接受用户自己的商品图描述，不做 NSFW 检测（M7 在 2-2）；验收时若出现异常告诉我 |
