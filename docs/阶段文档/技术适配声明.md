## 1. 产品形态判断

- **产品类型与核心任务**：多媒体创作 Agent。把"商品图/SKU 表"和"剧本"两类输入，变成"可交付的图片素材"和"可执行的分镜表 + 关键帧"。核心不是聊天，是**批量生产 + 一致性控制 + 成本控制**。
- **核心交互**：**分阶段确认**。
  - 电商线：上传 → 生成单 SKU 试跑图 → **你确认** → 批量 → 质检 → 导出
  - 短剧线：剧本 → 分镜表 → **你编辑确认** → 关键帧生成 → 导出
  - 两条线都要求"先看一张、确认后再批量"，这是 PRD §6.1/§6.2 写死的。
- **开发路径**：**纵向切片**（不是后端先行）。
  理由：本产品的核心价值必须"用眼睛看"才能判断——图对不对、颜色像不像、logo 糊没糊、角色崩没崩脸。仅靠 JSON 和自动化测试无法判断质量。手册第五节也明确：产出是"图片视频或需要人工确认的阶段结果"时，必须做最小可视化界面。
- **验收界面**：**纵向切片界面（保留到正式产品）**。
  ⚠️ 这是需要你确认的一项：本项目的验收界面从第一版起就按**正式前端标准**开发（有移动端适配、要过 lint/类型检查/生产构建），不是阶段 2 用完就丢的临时 HTML 页。理由同上——界面就是产品本身，不是壳。
- **上线档位**：**过渡档**（台账 D9）。内部试用 3-5 人，不办企业认证，单实例、不能扩容，写入即备份。
- **当前阶段范围**（阶段 2，拆成两个子阶段）：

| 子阶段 | 做什么 | 验收标准 |
| --- | --- | --- |
| 2-1 | 骨架 + 电商线最小闭环：项目管理、资产上传、模型网关 + 预算守卫、单 SKU 生成主图、试跑→确认→批量、基础一致性检查、导出 | 3 个真实 SKU 跑通，单张成本 ≤¥0.10，颜色 ΔE≤3 |
| 2-2 | 短剧线最小闭环：剧本输入、分镜表生成与编辑、关键帧生成、导出 | 一集 10-15 镜头跑通，分镜可编辑，关键帧采纳率 ≥70%（阶段 2 用样例打分校准） |

## 2. 采用的默认方案

| 层 | 方案 | 采用原因（一句话） |
| --- | --- | --- |
| 后端语言 | Python 3.12.x（本机已装 3.12.15） | 与已装环境一致，AI/图像生态最完整 |
| 后端框架 | FastAPI | 同步、异步、SSE 流式都直接支持，适合长任务进度推送 |
| 数据校验 | Pydantic | 模型输出必须结构化校验（PRD 要求 11 个核心实体） |
| 后端测试 | pytest | 手册默认；支持 mock 模型调用做离线测试 |
| 代码管理 | Git（已初始化，3 条提交） | `verify.sh` 的密钥检查依赖 Git 仓库 |
| 数据库 | **SQLite + SQLAlchemy** | 触发条件：11 个核心实体（Tenant/Project/Asset/Job/Run/QAReport/UsageRecord…）+ 批量任务状态 + 成本统计，单文件数据不够 |
| 文件存储 | **本地磁盘目录**（`data/assets/`） | 图片是二进制大文件，不能进数据库；MVP 阶段不引入云 OSS（避免过早产生云费用） |
| 长任务 | **数据库任务表 + 后台线程** | 触发条件：批量生成 100 张需并发，但不需要多实例共享队列；不引入 Redis/Celery |
| 流式交互 | **SSE** | 批量生成进度、分镜表逐字生成需要逐步展示；SSE 以 `done`/`error` 收尾 |
| 前端 | **Next.js + React + TypeScript + Tailwind** | PRD 终端是 Web；手册第四节 Web 默认方案 |
| 前端数据层 | 同源代理 `/api/*` → 后端 | 浏览器端不跨域，不暴露后端地址 |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 何时重新评估 |
| --- | --- | --- | --- | --- |
| 关系型数据库优先 PostgreSQL | SQLite | 过渡档单实例，无并发写压力 | 上线后仍是单实例，不能扩容 | 办下企业认证 / 并发写入出现锁冲突时 |
| 生产用对象存储 | 本地磁盘 | 避免阶段 2 就产生云费用 | 备份要连文件目录一起备 | 阶段 4 上线 |
| 任务队列（Celery） | DB 任务表 + 线程 | 并发只需 20 图/3 视频 | 进程重启会让"运行中"的 job 变成孤儿，需启动时标记为失败可重试 | 需要多实例或长任务跨重启续跑时 |
| 自建一致性模型（DINO/ArcFace） | VLM API 打分 + 本地 ΔE 计算 | 与"不自建 GPU"冲突 | 打分有 API 成本（约 ¥0.001-0.01/次），且精度依赖供应商 | 月量上来、API 打分成本超过自建时 |
| 完整 RBAC + 多租户 + 计费看板 | 单租户 + 邀请码 | 台账 D9 过渡档，D10 范围收窄 | 不能对外注册，不能分账 | 对外发布前 |
| 完整 I2V / 轻动效 / 时间线 | 不做 | 台账 D10 | 短剧线只能交付"分镜表 + 关键帧" | PRD P1 |
| 场景图 / 详情图 / 多风格变体 | 只做**主图** | 台账 D10 | 电商线交付物只有主图 | 阶段 2-1 验收通过后 |
| 已有 `mvp/` 骨架搬入 | 参考其设计重写进 `backend/` | 它是单机 CLI（无 HTTP/DB/多租户），搬入等于架构翻修 | 保留其成本守卫逻辑 + 8 个测试用例的思路 | 不适用 |
| PRD §12 的 8-10 周里程碑 | 按子阶段重排（2-1 / 2-2 / 3 / 4） | PRD 里程碑与 P0 全量范围不匹配 | 里程碑不再是承诺，以每个子阶段闸门为准 | 不适用 |
