## 1. 本阶段目标

**用一句产品语言描述用户完成了什么：**

> 用户在任何意外情况下（网络断、关页面、服务重启、任务失败）都能回来接着干，并且清楚知道"我的图现在到哪一步了、要不要重来、会不会重复扣钱"。

具体说，就是把「单张主图」这条闭环从"顺利时能用"提升到"出问题时也不会懵"。

## 3. 用户流程

1. 打开 `/` → 看到项目列表（或空状态）→ 点「新建项目」→ 填名字 → 创建成功回到列表
2. 点进项目 → 上传商品图 → 填商品名（必填）/ 类目 / 卖点 / 主色
3. 点「生成主图」（唯一彩虹 CTA）→ 按钮进入 `submitting`（禁用）→ 转 `queued` → 转 `running`（SSE 阶段文案）
4. **异常分支**：
   - 网络断 → `disconnected`，界面显示「连接中断，正在回查…」，自动 `GET /api/jobs/{id}`；后端仍在跑就重建 SSE，已结束就直接显示结果
   - 用户等不及 → 点「停止等待」（关 SSE，任务继续，文案写明）或点「取消任务」（调后端 cancel，任务真的停）
   - 任务失败 → 显示原因 + 错误码 + 「重试一次」；预算不足类失败不给重试按钮
5. 成功 → 出图 + 成本 + 耗时 + 「下载原图」
6. 关掉浏览器再回来 → 打开同一项目 → 自动显示最近一次成功结果（不重跑、不重复扣费）

| 状态 | `/` 项目列表 | `/projects/[id]` 项目详情 |
| --- | --- | --- |
| `idle` | 显示「新建项目」与空状态引导 | 显示上传框与表单；无图时「生成主图」禁用并说明原因 |

| `queued` | N/A | 蓝色胶囊「排队中」+ 文案「已受理，马上开始」 |
| `running` | N/A | 蓝色胶囊「生成中」+ SSE 阶段文案（正在准备 / 正在调用模型）+ 骨架屏 |
| `streaming` | N/A | **N/A**：本产品无逐字文本流；进度由 `status` 事件表达，不做假流式 |

| `succeeded` | 卡片显示「N 次生成」+ 素材数 | 出图 + 成本 + 耗时 + 「下载原图」；历史区出现缩略图 |
| `partially_succeeded` | N/A | **N/A（3-1）**：单任务无部分成功。2-2 批量的「18 成功 / 2 失败」启用此状态 |
| `failed` | 列表加载失败：红条 + 「重试」 | 红底卡：原因 + 错误码 + 「重试一次」；`BUDGET_EXCEEDED` 不显示重试按钮 |
| `cancelled` | N/A | 灰胶囊「已停止」+ 文案「已完成的结果已保留」+ 「重新生成」 |
| `disconnected` | 顶部黄条「连接中断」+ 「重试」 | 「连接中断，正在回查…」→ 自动 `GET /api/jobs/{id}` → 依真实状态落到 succeeded/failed/running |
| `stale` | N/A | 未知状态 → 「状态未知，请刷新」+ 刷新按钮；**不显示为成功也不显示为失败** |
| `loading` | 3 张骨架卡（**不显示"还没有项目"**） | 整页骨架：左表单块 + 右结果块 |

## 5. 接口契约

### 5.1 新增：取消任务

```
POST /api/jobs/{id}/cancel
```

- **请求**：无 body
- **成功返回**（202）：
  ```json
  { "job_id": "…", "status": "cancelled", "cancel_requested": true }
  ```
  - `queued` → 直接 `cancelled`
  - `running` → 返回 `status: "running", cancel_requested: true`，执行器在下一个检查点停止
- **错误**：
  - 404 `NOT_FOUND` 任务不存在
  - 409 `STATE_CONFLICT` 任务已 `succeeded` / `failed` / `over_budget`（不能取消已结束的）
- **超时与重试**：普通短请求，前端 10 秒超时；失败**不自动重试**（取消是幂等语义但重复调用会 409，前端只提示）
- **Mock 与真实接口切换**：前端 `features/api/client.ts` 统一封装，测试里替换该模块

### 5.2 既有接口（不变）

| 接口 | 用途 | 前端处理 |
| --- | --- | --- |
| `GET /api/projects` | 列表 | 失败 → `failed`；空 → `empty` |
| `GET /api/projects/{id}` | 详情 + `recent_jobs` | 404 → `not_found` |
| `GET /api/jobs/{id}` | 断线回查真实状态 | 用于 `disconnected` 恢复 |
| `GET /api/jobs/{id}/events` | SSE | `status/heartbeat/done/error`；**无 `done` 的关闭 → `disconnected`**，不得当成功 |
| `POST /api/projects/{id}/generations` | 创建任务 | 已禁用重复提交；503 `MODEL_NOT_CONFIGURED` 直接提示去填 Key |

## 6. 实现方案

### 6.1 路由

| 路径 | 类型 | 说明 |
| --- | --- | --- |
| `/` | Client Component | 首屏拉 `/api/projects` + `/api/health` |
| `/projects/[id]` | Client Component（`useParams`） | 拉详情 + 成本；订阅 SSE |

### 6.2 组件结构

```
app/
├── layout.tsx                    TopNav + main 容器
├── page.tsx                      项目列表
└── projects/[id]/page.tsx        项目详情
components/
├── layout/TopNav.tsx
└── ui/{Button,Card,EmptyState,Skeleton,StatusTag,Divider}.tsx
features/
├── api/{client.ts,types.ts}
├── jobs/{status.ts,useJobEvents.ts}
└── generation/components/{UploadBox,ResultPanel}.tsx
```

### 6.3 状态来源

| 状态 | 来源 | 存放 |
| --- | --- | --- |
| 项目 / 资产 / 历史任务 | `GET /api/projects/{id}` | 页面 `useState` |
| 当前任务状态 | SSE `status` + `done`/`error` | `useJobEvents` 内部（按 jobId 派生，防串台） |
| 断线后的真实状态 | `GET /api/jobs/{id}` | 写入 `useJobEvents` 的 state |
| 取消请求中 | 本地 `cancelling` | 页面 `useState` |

### 6.4 流式 / 轮询

- 主通道：SSE（`EventSource`），GET，无需自定义头。
- 断线：`error` 事件无 `data` → 视为连接断开 → **先 `GET /api/jobs/{id}` 查真实状态** → 非终态才重连（最多 2 次，退避 1s/2s）→ 仍失败显示 `disconnected` + 手动重试按钮。
- 不在每个组件各自开 SSE；一个页面同一时刻最多 1 条连接。

### 6.5 响应式处理

| 宽度 | 布局 |
| --- | --- |
| ≥1024 | 左表单 380px + 右结果自适应 |
| 768-1023 | 左右仍并排，表单收窄 |
| <768 | 单列堆叠：上传 → 表单 → 结果 → 历史 |
| 390 | 导航收为一行（隐藏阶段标签）；结果图 `max-h` 限制；无横向滚动 |

### 6.6 安全和隐私

- 前端不读任何模型 Key；浏览器可见环境变量只允许 `NEXT_PUBLIC_*`（当前一个都没用）。
- 错误信息只展示后端 `message`，不展示堆栈；`verify.sh` 第 2 项扫描前端构建产物。
- 上传只在客户端做类型预检，**真实校验以后端为准**（扩展名 + Pillow 解码 + MIME 三重）。
- 不引入任何第三方统计脚本 / CDN 字体 / 追踪。

## 8. 风险与回退

| 风险 | 影响 | 降级方案 | 回退方式 |
| --- | --- | --- | --- |
| 取消 `running` 任务无法真正中断 HTTP 请求 | 模型调用仍会完成并计费 | 检查点取消：置 `cancel_requested`，执行器在拿到结果后**丢弃产物、标记 cancelled、不记成本**（成本已产生但界面不显示为成功）；文案写「已停止，本次调用可能仍产生费用」 | 关闭取消入口，只保留「停止等待」 |
| 断线重连风暴 | 服务器压力 | 最多重连 2 次，退避 1s/2s；仍失败转手动 | 回到"手动刷新" |
| 真机验证无法完成 | 移动端体验未验证 | 如实记「待真机验证」，不写成已验证 | — |
| 16 状态改造引入回归 | 已验收的界面坏掉 | 每个状态都有对应 vitest + 浏览器实测 | `git revert` 本次提交，保留 2-1 界面 |
| 新增 cancel 接口改动后端 | 可能影响 2-1 已有测试 | 只新增路由与字段，不改既有行为；41 条测试必须保持全绿 | 删掉 cancel 路由，前端隐藏入口 |
