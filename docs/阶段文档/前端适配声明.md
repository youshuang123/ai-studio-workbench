## 3. 技术选择

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 框架与版本 | **Next.js 16.4.2（App Router）+ React 19.3.1 + TypeScript 5.9 strict** | 手册 §5 默认方案；已稳定运行 |
| 样式与组件策略 | **Tailwind 4 + 自建 6 个基础组件**（Button / Card / StatusTag / EmptyState / Skeleton / TopNav） | 不引入组件库：界面元素少，自建更贴合 Portrait 视觉；避免为"组件完整"引入用不上的依赖 |
| 数据请求与状态策略 | `fetch` + 组件内 `useState` + 自定义 hooks（`useJobEvents`） | 页面只有 2 个、状态不跨页共享，引入 Redux/Zustand 属于过度设计 |
| 流式通信策略 | **SSE（原生 EventSource）**，事件名 `status` / `heartbeat` / `done` / `error` | 手册 §10.1：单向推送优先 SSE；当前无需自定义请求头，EventSource 够用 |
| 表单方案 | 受控组件 + 前端即时校验 + 后端 Pydantic 双校验 | 前端校验只为即时反馈，**权限与数据校验以后端为准**（AGENTS.md 底线 7） |
| 测试方案 | **vitest + jsdom**（现有 19 条：格式化 / 状态映射 / 错误归一化 / 组件渲染） | 手册 §21；Playwright E2E 放到 3-2（需要真实模型与稳定数据，2-1 阶段做了浏览器实测替代，见证据包） |
| 部署环境 | 阶段 4 决定（过渡档：单实例 Next + Python） | 手册 §5 不预设 |

## 4. Agent 状态

### 4.1 后端状态 → 前端统一状态映射

| 后端 `generation_jobs.status` | 前端统一状态 | 界面表现 |
| --- | --- | --- |
| （未创建） | `idle` | 显示上传与表单；无图时禁用生成按钮 |
| `queued` | `queued` | 蓝色胶囊「排队中」+ 文案「已受理，马上开始」 |
| `running` | `running` | 蓝色胶囊「生成中」+ SSE 阶段文案（正在准备 / 正在调用模型） |
| `succeeded` | `succeeded` | 出图 + 成本 + 耗时 + 下载 |
| `failed` | `failed` | 红底卡：原因 + 错误码 + 「重试一次」 |
| `over_budget` | `failed`（子类 budget） | 红底卡 + 「预算不足」原因，**不提供重试**（重试也过不去） |
| `cancelled` | `cancelled` | 灰胶囊「已停止」+ 保留已有结果 + 可重新生成 |
| 未知 / 空 | **`stale`** | 「状态未知，请刷新」，**不当成功也不当失败** |
| SSE 断开且无 `done` | `disconnected` | 「连接中断」+ 自动按 jobId 回查后端真实状态 |
| HTTP 404 | `not_found` | 「项目不存在」+ 返回列表 |
| 网络不可达 | `failed`（`NETWORK_ERROR`） | 「连不上服务，请确认后端已启动」+ 重试 |

> `waiting_user` 与 `partially_succeeded` 在 3-1 里为 N/A（单任务无此状态），会在 3-2（批量试跑确认）与 2-2 一起启用。

### 4.2 等待用户确认的方式

- 3-1：生成前的表单即确认点——不填商品名不允许提交；生成按钮是唯一彩虹 CTA，点击后立刻进入 `submitting` 并禁用。
- 3-2：批量「试跑 → 确认批量」双确认（对应决策 D8）。

### 4.3 取消、重试、断线恢复

| 能力 | 做法 |
| --- | --- |
| 取消 | **前端明确区分两件事**：①「停止等待」= 关闭 SSE，任务在后端继续（文案直接写明）；②「取消任务」= 调后端 `POST /api/jobs/{id}/cancel`，后端置为 `cancelled`。3-1 补齐后者 |
| 重试 | 只在 `failed` 时可重试；重试前先查后端状态，避免把已成功的任务再跑一次（避免重复扣费） |
| 断线恢复 | 页面加载时先 `GET /api/projects/{id}` 拿最近任务；若该任务非终态，则重建 SSE；若已终态，用「最近一次成功结果」兜底显示 |
| 防重复提交 | 前端：提交中禁用按钮；后端：状态机 `queued/running` 时拒绝重复 retry（409） |

### 4.4 任务 ID 与恢复入口

- 任务 ID 不放在 URL 里（一个项目会有多次生成，URL 只标识项目）。
- 恢复入口：`/projects/{id}` → 后端返回 `recent_jobs`（最近 10 条）→ 取最近一条非终态任务续订阅，或取最近一次成功结果兜底展示。

## 6. 偏离本手册的地方

| # | 偏离项 | 原因 | 影响 |
| --- | --- | --- | --- |
| 1 | **不引入全局状态库** | 只有 2 个页面，状态不跨页共享 | 若 3-2 批量页出现跨页共享（批次进度），届时评估引入 |
| 2 | **不引入组件库**（shadcn/MUI） | 界面元素少，自建 6 个组件即可；组件库会带来与 Portrait 冲突的默认样式 | 需要自己维护无障碍属性（已在 3-1 补齐） |
| 3 | **暂不引入 Playwright E2E** | 2-1 的验收用真实浏览器实测替代（截图 + Console 检查见证据包）；E2E 需要稳定数据与真实模型，成本高 | 3-2 引入，用于覆盖"批量 + 导出"这条更长的链路 |
| 4 | 视觉按 `docs/设计参考/DESIGN.md`（Portrait）而非手册附录示例 | 产品经理指定 | 与前端手册无冲突（视觉属于按项目选择层）；逐条偏离见下 |
| 4.1 | 字体：Switzer / Basier Circle → 系统字体 + 复刻负字距 | 商业字体无授权，CDN 引入离线构建会失败 | 字形不同，紧字距的"雕刻感"保留 |
| 4.2 | 布局：官网式居中 hero → 工具式左表单右结果 | 产品是操作台不是官网 | 保留药丸导航与 24px 相纸卡；不做倾斜装饰 |
| 4.3 | 大标题 76px → 桌面 46px / 手机 30px | 工具界面不需要撑场面 | 保留负字距与 600 字重 |
| 4.4 | 相纸倾斜 3-6° → 不倾斜 | 工作台里倾斜会点不准 | 保留圆角 + 发丝边 + 极轻阴影 |
| 4.5 | 段落居中 → 左对齐 | 表单居中降低扫读效率 | DESIGN.md 自身注明"居中只是一次性排版选择" |

**未偏离**：单一墨色、单彩虹规则、24/28/16/9999 圆角体系、阴影 ≤8% 黑、状态胶囊 pastel 规则——全部照做。
