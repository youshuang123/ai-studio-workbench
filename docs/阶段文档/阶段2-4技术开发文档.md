## 〇、这条线跟电商线的区别

| | 电商线（已完成） | 短剧线（本阶段） |
| --- | --- | --- |
| 输入 | 商品图 + SKU 表 | **一段剧本文字** |

## 二、技术方案

### 2.1 模型

| 用途 | 模型 | 单价（估算） |
| --- | --- | --- |
| 剧本 → 分镜表 | `deepseek-ai/DeepSeek-V4-Flash`（硅基流动，同 Key） | ≈¥0.01-0.03/集 |
| 角色参考图 | `Tongyi-MAI/Z-Image-Turbo`（现有） | ¥0.03/张 |
| 关键帧草稿 | 同上 | ¥0.03/张 |
| 关键帧精修 | `Qwen/Qwen-Image-Edit-2509`（2-3 已接） | ¥0.30/张 |
| 轻动效合成 | FFmpeg（本地，imageio-ffmpeg） | ¥0 |

**不需要新 Key。**

### 2.2 数据模型（3 张新表）

```sql
dramas                 -- 一部短剧（一个项目下可以有多个）
  id, project_id, title, script_text, style, status,
  created_at, updated_at

scenes                 -- 场次
  id, drama_id, index, title, location, time_of_day, summary

shots                  -- 镜头（分镜表的一行）
  id, drama_id, scene_id, index,
  shot_size,        -- 景别：远景/全景/中景/近景/特写
  camera,           -- 机位：平视/俯拍/仰拍/过肩
  action,           -- 动作描述
  dialogue,         -- 台词
  duration_sec,     -- 时长（2-8 秒）
  continuity,       -- 连续性说明（服装/道具/情绪）
  mood,             -- 情绪
  character_ids,    -- JSON 数组
  job_id,           -- 关键帧对应的生成 job
  created_at

characters             -- 角色
  id, drama_id, name, appearance, costume, personality,
  ref_asset_id,     -- 角色参考图
  created_at
```

`shots.job_id` 指向 `generation_jobs`，所以关键帧的生成、精修、质检、成本**全部复用现有机制**。

### 2.3 分镜表生成（LLM）

**Prompt 要点**（严格 JSON 输出）：

```
你是短剧分镜师。把下面的剧本拆成分镜表。

剧本：
{script}

角色：{characters}

要求：
1. 按场次拆，每场 3-6 个镜头；
2. 每镜头必须有：shot_size / camera / action / dialogue / duration_sec / mood / continuity
3. duration_sec 在 2-8 之间，一场总时长控制在 30-60 秒
4. 台词保留原剧本措辞，不要改写
5. 只输出 JSON：{"scenes":[{"title":"","location":"","time_of_day":"","summary":"","shots":[...]}]}
```

- 输出经 Pydantic 校验；不合格自动重试 1 次；再失败报错（不静默）
- 分镜表落库后可编辑，编辑直接改 `shots` 表

### 2.4 关键帧生成

每个镜头一条 job，`prompt` 由分镜字段拼成：

```
{shot_size}，{camera}，{action}，{mood}情绪；
角色：{name}（{appearance}，{costume}）；
场景：{location}，{time_of_day}；
风格：{style}；
画面中不要出现任何文字。
```

- 有角色参考图时：走**图生图**（`Qwen-Image-Edit`）保证长相一致 → 贵（¥0.3/张）
- 无参考图：走**文生图**（¥0.03/张）
- 默认：**先全部文生图（草稿）**，你挑中的再精修 → 与 2-3 的两段式完全一致

### 2.5 轻动效合成（2-4a 已验证）

每个镜头按 `shot_size` 决定运镜：

| 景别 | 运镜 |
| --- | --- |
| 远景/全景 | 缓慢推近（zoom 1.0→1.10） |
| 中景 | 水平平移（pan 左→右） |
| 近景/特写 | 轻微推近 + 上移（zoom 1.0→1.06） |

镜头之间用 `xfade` 转场（0.4 秒），最后输出 1080p / 25fps / H.264 MP4。

时长 = 各镜头 `duration_sec` 之和（去掉转场重叠）。

### 2.6 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/projects/{id}/dramas` | 创建短剧（标题 + 剧本 + 风格） |
| GET | `/api/dramas/{id}` | 详情（含场次、镜头、角色） |
| POST | `/api/dramas/{id}/storyboard` | 调 LLM 生成分镜表（覆盖或追加） |
| PATCH | `/api/dramas/{id}/shots/{shot_id}` | 编辑单个镜头 |
| POST | `/api/dramas/{id}/shots` | 新增镜头 |
| DELETE | `/api/dramas/{id}/shots/{shot_id}` | 删除镜头 |
| POST | `/api/dramas/{id}/characters` | 新增角色 |
| POST | `/api/dramas/{id}/characters/{cid}/ref` | 生成角色参考图 |
| POST | `/api/dramas/{id}/keyframes` | 为所有缺关键帧的镜头生成（并发 3） |
| POST | `/api/dramas/{id}/shots/{shot_id}/keyframe` | 单镜头重生成 |
| POST | `/api/dramas/{id}/compose` | 合成轻动效视频 |
| GET | `/api/dramas/{id}/export` | 导出 ZIP（MP4 + 分镜 CSV + 关键帧） |
| GET | `/api/dramas/{id}/events` | SSE 进度 |

### 2.7 前端

新页面 `/projects/[id]/dramas/[dramaId]`，五段式：

| 段 | 内容 |
| --- | --- |
| 01 · 剧本 | 剧本文本框 + 风格选择 + 「生成分镜表」 |
| 02 · 分镜表 | 表格：场次分组，每行可编辑（景别下拉、动作/台词文本、时长数字、删除/上下移） |
| 03 · 角色 | 角色卡片：名称/外貌/服装 + 「生成参考图」 |
| 04 · 关键帧 | 按镜头排的相纸卡网格，每张可重生成 / 精修 / 看质检分 |
| 05 · 成片 | 「合成视频」→ 进度 → 播放器 + 下载 |

## 五、验收清单（你照着点）

1. **建短剧** → 粘一段 200 字剧本 → 选风格「都市」
2. **生成分镜表** → 约 10-20 秒 → 出 2 场 8 个镜头
3. **改分镜** → 把第 3 镜头的台词改一句、删掉第 5 镜头、把第 6 移到第 4 前面 → 刷新后仍然生效
4. **加角色** → 「林小满 / 25 岁女性 / 齐肩黑发 / 米色针织衫」→ 生成参考图
5. **生成关键帧** → 8 张 → 约 40 秒 → 网格出现 8 张图
6. **精修 2 张** → 弹窗确认 ¥0.60 → 精修后与草稿对比
7. **合成视频** → 8 个镜头 → 约 30 秒 → 出 MP4，能播放，有推拉和转场
8. **导出** → ZIP 里有 MP4 + 分镜表 CSV + 关键帧
9. **成本** → 显示分镜 / 关键帧 / 精修 三项分开
10. **重启不丢** → 我重启后端 → 分镜表、关键帧、视频都在

## 六、风险

| 风险 | 应对 |
| --- | --- |
| LLM 分镜质量不稳定 | 严格 schema 校验 + 重试 1 次；分镜表可手改（这是核心，不依赖模型一次到位） |
| 角色一致仍靠图生图，不是真 LoRA | 已如实说明；质检的 `color_consistency` 换成"角色一致性"维度 |
| 合成很慢（8 镜头 × 2.6s 渲染） | 实测 2-4a 3 镜头 7 秒渲染 <5 秒；8 镜头预估 <15 秒 |
| 无声视频 | 本阶段不接 TTS，P1 再加 |
| 成本误点 | 合成与精修都要先确认价格 |
