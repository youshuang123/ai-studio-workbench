## 1. 评估原则

1. **按场景定模型，不按榜单定模型。** 商品图、角色一致性、文字渲染、镜头运动是四种能力。
2. **多模型矩阵 + 统一网关 + 路由/降级。** 业务不直接绑死某一家 API。
3. **一致性优先于单张惊艳。** 商业工作台看的是批量可用率。
4. **自托管保成本/数据/可控；API 保质量上限/长尾/突发。**
5. **量化必须过质量门禁。** 不能为了省显存牺牲最终出片。
6. **License 是硬门槛。** 不能商用的模型，分数再高也不能进生产。

### 3.1 权重

| 任务 | 质量 | 一致性 | 可控性 | 成本 | 时延 | License | 指令遵循 | 生态 |

| 视频生成 | 25% | 30% | 20% | 15% | 5% | 5% | — | — |
| LLM 编排 | 30% | — | — | 20% | 10% | 5% | 25% | 10% |

> 权重可按业务调整。例如：如果主打电商，提升“一致性”和“可控性”；如果主打短剧精品，提升“质量”和“运动一致性”。

**解读：**

- 追求质量上限 + 快速上线：**Seedream 4.0 / Nano Banana** 分数高，但成本和供应商锁定要接受。
- 草稿/批量探索：**FLUX.1 [schnell]** 成本/速度最好，不用于最终出图。

## 4. 精度与量化对比

### 4.1 推荐精度

| 模型类型 | 质量基线 | 生产默认 | 备注 |
|---|---|---|---|
| LLM | BF16 | FP8 E4M3 | 32B 路由可 AWQ INT4；KV cache 可 FP8 |
| T2I / 编辑 DiT | BF16 | FP8 | 保留 norm/softmax 为 FP16 |
| Video DiT | BF16 | FP8 + sequence parallel | VAE 保持 BF16/FP16 |
| VAE / text encoder | FP16/BF16 | FP16/BF16 | 对数值敏感，不建议量化 |
| 抠图 / 超分 CNN | FP16 | INT8 | TensorRT 量化 |
| 安全分类器 | BF16 | FP8/INT8 | 需验证误拦截率 |

### 4.2 量化对比表（示例，需实测）

| 模型 | 精度 | 权重显存（约） | 吞吐 | 质量变化 | 建议 |
|---|---|---:|---|---|---|
| FLUX.1 [dev] 12B | BF16 | ~24GB | 1.0x | 基线 | 质量验收 |
| FLUX.1 [dev] 12B | FP8 | ~12GB | 1.5–2.0x | <2% | 生产默认 |
| FLUX.1 [dev] 12B | INT8 | ~10GB | 1.8–2.2x | 2–5% | 谨慎，需实测 |
| Wan2.2 14B | BF16 | ~28GB | 1.0x | 基线 | 质量验收 |
| Wan2.2 14B | FP8 | ~14GB | 1.5–2.0x | <2% | 生产默认 |
| Qwen3-32B | BF16 | ~64GB | 1.0x | 基线 | 质量验收 |
| Qwen3-32B | FP8 | ~32GB | 1.5–2.0x | <2% | 生产默认 |
| Qwen3-32B | AWQ INT4 | ~18GB | 2.0–2.5x | 2–5% | 路由/低优先级 |

> 显存为权重估算，不含激活、KV cache、VAE 和框架开销；以实际压测为准。

### 4.3 量化门禁

1. 同一 seed / prompt / 参考图，对比 BF16 与量化版本；
2. 关键指标下降 ≤2%（指令遵循、一致性、OCR、VBench）；
3. 安全指标零回退（误拦截率、漏放率）；
4. 无明显伪影、闪烁、文字崩坏；
5. p95 时延或单位成本改善 ≥30%；
6. 通过后才进入 canary。

## 6. 成本模型与自托管 vs API

### 6.1 公式

**自托管单位成本：**

```text
单张/单条成本 = GPU 小时单价 / 每小时吞吐
              + 存储/带宽
              + 运维分摊（建议按 20%–40% 计）
              + 失败重试损耗
```

**API 单位成本：**

```text
单张/单条成本 = 单价 × (1 + 重试率)
```

**盈亏平衡量：**

```text
盈亏平衡量 = 自托管固定成本 / (API 单价 - 自托管单位成本)
```

### 6.2 示例假设（请替换成你的真实价格）

| 参数 | 示例值 |
|---|---|
| H100 按需价 | $2.5/小时 |
| L40S 按需价 | $1.2/小时 |
| 存储 | $0.02/GB/月 |
| 运维分摊 | 30% |
| FLUX dev 吞吐 | 300 张/小时（保守） |
| Wan2.2 5 秒视频耗时 | 5 分钟/条 |
| API 图片价 | $0.02–$0.08/张 |
| API 视频价 | $0.5–$3/条（5 秒） |

### 6.3 示例测算

**FLUX dev 自托管：**

```text
$2.5 / 300 = $0.0083/张
+ 30% 运维 = $0.0108/张
```

对比 API $0.02–$0.08/张：**高 volume 时自托管明显更便宜**，但需要承担 GPU 空闲、模型维护、故障处理。

**Wan2.2 5 秒视频自托管：**

```text
$2.5 × (5/60) = $0.208/条
+ 30% 运维 = $0.27/条
```

对比 API $0.5–$3/条：**批量短剧自托管有优势**；精品镜头仍建议用 Kling/Veo API。

**LLM 自托管：**

```text
Qwen3-32B on L40S：$1.2/小时
若吞吐 2000 次/小时，单次 $0.0006
```

对比 API：低 volume 用 API 更省心；高 volume + 数据敏感时自托管更合适。

### 6.4 推荐组合

| 阶段 | 图片 | 视频 | LLM | 理由 |
|---|---|---|---|---|
| MVP 低 volume | FLUX schnell/dev 自托管 + Seedream API 兜底 | Kling/Veo API 为主，Wan2.2 试跑 | DeepSeek API | 快速上线，少运维 |
| 增长期 | FLUX dev/Kontext 自托管为主 | Wan2.2 自托管标准 + Kling 精品 | Qwen3-32B 自托管 | 成本可控，质量分层 |
| 规模化 | 自托管主力 + API 长尾 | Wan2.2 批量 + API 精品 | Qwen3-235B/32B 自托管 | 单位成本最低，数据可控 |

## 7. 评估计划

### 7.1 金标集

- 电商：50 个 SKU × 6 个场景 × 3 种尺寸；
- 短剧：20 个角色 × 50 个镜头 × 3 种风格；
- 通用：300–500 条 prompt，覆盖文字、手部、透明/反光、多人、遮挡、运动；
- 安全：200 条红队 prompt + 100 张风险图；
- 所有样本固定 seed、参考图、模型版本。

### 7.2 指标

| 维度 | 指标 |
|---|---|
| 文生图 | 指令遵循（VLM 1–5 / GenEval）、HPSv2/ImageReward、OCR 文字准确率、伪影率 |
| 商品一致性 | 颜色 ΔE、logo OCR、形状 DINO/IoU、SKU 属性 VLM 准确率 |
| 角色一致性 | ArcFace 余弦、DINO 相似度、人工偏好胜率 |
| 视频 | VBench 主体一致性/运动平滑/闪烁、首尾帧一致性 |
| 口型/音频 | LSE-D、MOS |
| 系统 | p50/p95 时延、吞吐、GPU 利用率、单张/单分钟成本 |
| 业务 | 首版通过率、人工修图率、采纳率、交付时长 |
| 安全 | 漏放率、误拦截率、人工复核率 |

### 7.3 上线门禁

1. 离线金标集通过；
2. BF16 vs FP8/INT8 对比通过；
3. shadow 运行 1–2 周，无严重事故；
4. canary 5% 用户，业务指标不下降；
5. A/B 通过后全量；
6. 模型注册表记录版本、评测报告、回滚点。

| 音频 | CosyVoice 2 + Whisper large-v3 | 中文 TTS/ASR |

### 一句话

> **MVP 用“开源模型打底 + API 兜上限 + 三档路由 + 一致性包 + 自动 QA”的组合，先把两条工作流跑通，再用真实数据决定哪些模型值得自托管、哪些继续用 API。**
